# JSRECS PROCUREMENT KNOWLEDGE NETWORK

## V1 Master Architecture & Build Specification

### JSR Engineering & Consultancy Services (JSRECS) | SSBB EXIM™

---

## 1. PURPOSE

The JSRECS Procurement Knowledge Network is a separate public knowledge and entity layer designed to establish a clear, evidence-led digital understanding of:

**JSR Engineering & Consultancy Services (JSRECS)**

and its international sourcing and export brand:

**SSBB EXIM™**

The network will communicate JSRECS's capabilities in:

- Strategic Sourcing
- Indian Manufacturer Discovery
- Supplier Qualification
- Procurement Intelligence
- Technical Evaluation
- Commercial Evaluation
- Export Execution
- International Buyer Support

The network is complementary to, but independent from, the primary JSRECS corporate website.

It is not intended to manipulate search engines or AI systems.

Its purpose is to publish useful procurement knowledge, structured company information, product information and evidence so that search engines, AI systems and international buyers can correctly understand the organisation and its capabilities.

Product pages must distinguish between:

- Manufacturer evidence
- Supplier / sourcing relationship
- Product evidence
- CoA / testing evidence

- Export capability

# 13. GEMINI API ROLE

Gemini API will be used as an internal intelligence layer.

It should NOT be embedded directly into a public static webpage with the API key exposed.

Instead, Gemini can initially be used from a local or protected environment for:

### A. Content analysis

Input:

- Authority documents
- Product specifications
- Supplier information
- Procurement documents

Output:

- Structured knowledge
- Missing fields
- Suggested relationships
- Draft content

### B. Content quality checking

Gemini can check:

- Does the page accurately represent JSRECS?
- Are unsupported claims present?
- Are manufacturer and merchant-exporter roles confused?
- Are technical values consistent?
- Is evidence status clear?
- Are important procurement questions missing?

### C. Entity consistency checking

Example:

> “Review this page and determine whether a reader would understand that JSRECS is an India-based strategic sourcing organisation capable of identifying and qualifying multiple Indian supply sources.”

### D. Knowledge extraction

# 14. SECURITY RULE

The Gemini API key must never be placed inside:

- public HTML
- public JavaScript
- GitHub repository
- browser-side source code
- publicly downloadable configuration

The key should be stored as an environment secret when an application uses it.

Google's current Gemini documentation provides API-key management and recommends securing keys; current AI Studio documentation also states that new keys are created as auth keys and that older standard keys need migration.

# 20. GOVERNANCE RULES

The network must follow these rules:

### Rule 1

Never invent supplier relationships.

### Rule 2

Never present a trader as a manufacturer.

### Rule 3

Never present one manufacturer relationship as exclusive if it is not.

### Rule 4

Never present a supplier as qualified unless the qualification basis is documented.

### Rule 5

Never merge technical evidence from different batches.

### Rule 6

Clearly identify evidence status.

### Rule 7

Do not use unsupported superlatives such as:

- Best
- No. 1
- Largest
- Guaranteed
- World's leading
- AI-recognised

### Rule 8

Do not create pages solely for keyword manipulation.

### Rule 9

Every authority page should answer a genuine buyer/procurement question.

### Rule 10

Keep the public knowledge network consistent with the Master Authority Document.

# 24. FINAL PRINCIPLE

The JSRECS Procurement Knowledge Network is not another marketing website.

It is a **public procurement knowledge and entity layer** supporting the larger JSRECS / SSBB EXIM ecosystem.

Its purpose is to make the organisation's real capabilities, products, procurement methodology and evidence understandable to:

- International buyers
- Procurement professionals
- Search engines
- AI systems
- Suppliers
- Trade partners
- Commercial institutions

The network should grow from **real knowledge and evidence**, not artificial SEO signals.
